# SyncBridge アーキテクチャ

最終更新: 2026-10-16（Phase 0）

## 1. 構成

```
┌──────────── Maya (Python 3.9+) ────────────┐        ┌──────── After Effects ────────┐
│ maya_plugin/scripts/syncbridge_maya        │        │ after_effects/panel (CEP)     │
│   scene_timewarp  : Scene Time Warp の特定  │        │   HTML/JS: WebSocket 通信     │
│   anim_curve      : animCurveTT 読み書き    │        │        │ evalScript           │
│   exchange        : export / apply         │        │ after_effects/jsx             │
│   probe           : Phase 0 実機検証       │        │   syncbridge_ae_lib.jsxinc    │
│        │ import (同一プロセス)               │        │   syncbridge_ae.jsx / probe   │
│ src/syncbridge/core  ◄──────────────────────┼─┐      └──────────────┬────────────────┘
└────────────────────────────────────────────┘ │                     │
                                               │   Phase 0: JSON ファイル
                                               │   Phase 1+: ws://127.0.0.1:8765
┌──────────── Local Sync Server (別プロセス) ──┼─────────────────────┴───────────────┐
│ src/syncbridge/cli.py      (Phase 0 の変換ハブ)                                        │
│ src/syncbridge/server      (Phase 1: FastAPI/WebSocket、接続管理、リビジョン、競合)     │
│ src/syncbridge/core  ◄───── Time Mapping Core（純 Python、標準ライブラリのみ）          │
└────────────────────────────────────────────────────────────────────────────────────┘
```

### Time Mapping Core（`src/syncbridge/core`）

| モジュール | 役割 |
|---|---|
| `timebase.py` | 有理数 fps（`Fraction`）、Maya 時間単位名、フレームと秒の変換 |
| `curve.py` | 中立カーブ `TimeCurve`（入力秒 → 出力秒）、評価、アフィン変換、JSON |
| `ae_codec.py` | AE の Time Remap キー（速度・影響度）⇔ 中立カーブ |
| `maya_codec.py` | Maya の animCurveTT キー（フレーム、傾き、ハンドル長）⇔ 中立カーブ |
| `mapping.py` | `MappingContext`: Maya の時間軸と AE の時間軸の対応（原点、オフセット、スケール） |
| `sampler.py` | Precision モード: 適応的な区分線形の再サンプリング |
| `validation.py` | 誤差計測（出力フレーム単位）、`ErrorReport` |
| `transfer.py` | 変換パイプライン（デコード → 写像 → モード → エンコード → 検証） |
| `envelope.py` | 交換用エンベロープ（ファイル、将来の WebSocket メッセージ共通） |
| `testcurves.py` | 参照カーブ（単体テストとプローブで共用） |

## 2. データの流れ（Phase 0）

```
Maya → AE
  Maya: export_timewarp() ──► maya.timewarp.export
        { native(フレーム単位のキー), samples(Maya 自身の評価値), scene(fps/範囲/解像度), calibration }
  AE:   syncbridge_ae.jsx Export ──► ae.timeremap.export（対象レイヤーのコンプ fps、startTime など）
  PC:   cli maya2ae ──► ae.timeremap.apply { keys(AE 形式), context, report }
  AE:   syncbridge_ae.jsx Apply ──► 確認 → JSON バックアップ → undo グループで適用 → *_after.json
  PC:   cli readback apply after ──► AE が実際に評価した値と比較

AE → Maya
  AE:   Export ──► ae.timeremap.export { keys, samples(valueAtTime) }
  PC:   cli ae2maya ──► maya.timewarp.apply
  Maya: apply_timewarp() ──► 確認 → JSON バックアップ → undo チャンクで適用 → リードバック比較を表示
```

`transfer` の 1 回の変換は最大 3 つの誤差レポートを持つ。

| レポート | 比較対象 | 検出するもの |
|---|---|---|
| `source_fidelity` | 転送元カーブのデコード結果 vs 転送元アプリ自身の評価値 | 転送元アプリの接線解釈の誤り（H-MY-4/5, H-AE-3） |
| `conversion` | 出力キーを再デコードしたカーブ vs 写像後の転送元カーブ | コーデックやモードによる損失 |
| `readback` | 転送先アプリが適用後に評価した値 vs 送ったカーブ | 転送先アプリの解釈の誤り、単位・オフセットの誤り |

## 3. 設計判断（変更履歴）

仕様書 v0.1 からの変更と、Phase 0 で決めた方針。変更するときは理由とともにここへ追記する。

### D-1: ディレクトリ構成の変更（仕様 11 章からの変更）

- 仕様の `maya/` を **`maya_plugin/`** に変更した。
  **理由:** `maya/` を Python パッケージとして sys.path に置くと、Autodesk の `maya` モジュール
  （`import maya.cmds`）を隠してしまい、Maya 内で致命的な名前衝突になる。
- 仕様の `core/`, `server/`, `updater/` は **`src/syncbridge/` パッケージの下** に置いた。
  **理由:** `core` のような汎用名をトップレベルに置くと他のツールと衝突しやすい。また Maya とサーバーの両方から
  同じ `syncbridge.core` を import する必要がある。`src/` レイアウトにより、テストがインストール済みのコードを
  誤って参照する事故も防げる。

### D-2: 変換ロジックは Python に一元化する

- JSX は AE 形式のキーの読み書きとサンプリングだけを担い、Bezier の変換は実装しない。
- Phase 0 は CLI が変換ハブ、Phase 1 からはサーバーが同じ `syncbridge.core` を呼ぶ。Maya は同じプロセス内で core を import できる。
- **理由:** 変換を JS と Python で二重実装すると、精度の検証対象が 2 つになり、食い違いの原因になる（仕様 13 章 1・2）。

### D-3: 中立カーブは「明示的な 2D 3 次 Bezier（秒）」

- 各キーが in／out の補間（LINEAR／BEZIER／HOLD）とハンドル (dt, dv) を持つ。
- Maya の傾きと weight、AE の速度と影響度は、どちらもこの形式に損失なく写せる（範囲の制約を除く）。
- アフィン変換（オフセット、fps の違い、ソーススケール）を厳密に適用できる。

### D-4: Precision モードは LINEAR／HOLD キーだけを出力する

- 直線補間は Maya と AE で評価が一致するため、未検証の接線の数式（H-MY-4/5, H-AE-3/6/7）に依存しない。
- キーは既定でフレーム位置に置き（`key_subdivision=1`）、点と点の間もサブフレーム（既定 8 分割）で誤差を確認する。
- フレーム位置のキーだけでは許容誤差に収まらない箇所に限り、サブフレームのキーを追加する（`allow_subframe`）。
- 内部では許容誤差の 50% を目標に当てはめ（`FIT_MARGIN`）、最後に全範囲を再検証する。

### D-5: 適用後のリードバック検証

- 適用後に、転送先アプリ自身の評価値（Maya `keyframe -eval`、AE `valueAtTime`）をサンプルし、送ったカーブと比較する。
- 未検証の仮説が外れていても、誤ったデータを「成功」として扱わないための安全網。

### D-6: Maya 読み取り時の自己キャリブレーション

- weighted 接線の単位（H-MY-5）が未確定のため、読み取り時に候補のスケールを全て試し、
  Maya 自身の評価値に最もよく一致するものを採用する。採用した候補と誤差は export に記録する。

### D-7: Phase 0 では Scene Time Warp を新規作成しない

- 作成コマンドや内部構造が未確認のため、UI で作成済みのカーブを探して読み書きするだけにする。
- 2026-10-16 追記: Maya 2024 のプローブで、UI の作成コマンドが MEL の `sceneTimeWarp "add"` であることがわかった
  （H-MY-10）。ただし作成を実行したときの副作用（既存カーブの扱い、undo）は未確認のため、方針は維持する。
  自動作成は Phase 1 以降で、プローブで挙動を確認してから追加する。

### D-8: テストは標準ライブラリの unittest

- Maya の Python でもそのまま実行でき、外部依存がない。pytest からも実行できる。

### D-9: 時間軸の対応は `MappingContext` で明示する

- 「どの Maya フレームが、どのコンプ時間・ソース時間に対応するか」を暗黙にしない（仕様 4.3）。
- CLI の既定: `--origin` で Maya 側の原点フレームを指定し、AE 側のコンプオフセットはレイヤーの startTime。

### D-10: 転送は「評価範囲」で一致を判定する（2026-10-16 追加、R-20）

- Maya 2024 のプローブで、UI で作った Scene Time Warp が前後 Linear 外挿だとわかった。AE の Time Remap は範囲外で値を保持するだけなので、
  キーの範囲だけで一致を判定すると、コンプやレンダー範囲のうちキーの外側のずれを見落とす。
- そこで転送に評価範囲（転送先の入力時間）を持たせ、Precision は範囲外の外挿をキーに焼き込み、誤差レポートは範囲全体で計る。
  Editable は表現できない外挿を警告し、不合格として報告する（黙って捨てない、SPEC 5 章 6）。
- 既定の範囲は、Maya の再生範囲と AE のコンプ範囲。どちらも「利用者が見る時間」なので、これで一致すれば見た目は一致する。

### D-11: サーバーは FastAPI + uvicorn、開発環境はリポジトリ内の `.venv`（2026-10-16、Phase 1）

- 仕様どおり FastAPI。依存は `requirements-server.txt` にバージョンを固定し、リポジトリ内の `.venv`（Git 管理外）に入れる。
  PC の Python 本体には入れない（利用者の選択）。配布時は PyInstaller で EXE に含める（Phase 6）。
- uvicorn の WebSocket 実装は `websockets-sansio`（旧実装は非推奨警告が出るため）。
- `syncbridge.core` と `syncbridge.protocol`、`server/session.py` は標準ライブラリだけで書く（Maya のクライアントが import するため）。

### D-12: Maya のクライアントは標準ライブラリだけで書く（Phase 1-B で実装予定）

- Maya の Python に外部パッケージを入れずに済むようにするため。必要なのはテキストフレーム、ping/pong、close だけ。

### D-13: 変換手順は `core/jobs.py` に置き、CLI とサーバーで共有する（2026-10-16）

- Phase 0 の CLI にあった「オプション → 時間の対応 → 評価範囲 → 変換 → 読み戻しの検証」を移した。CLI とサーバーで結果が食い違わないようにするため。
- サーバーは、変換が許容誤差を超えたら転送先に適用を依頼しない（CLI はファイルを書くだけなので従来どおり書き出す）。

### D-14: Phase 1 の機能だけで先行配布する（2026-10-16、利用者の要望）

- タイムワープ転送が急ぎで必要なため、Phase 6 の一部（サーバーの EXE 化、インストーラー）を先に作り、0.1.0 として配布する（`docs/RELEASE.md`）。
- 利用者はターミナルを使わない前提: zip を解凍して `Install.bat` をダブルクリック。管理者権限は使わず、各ユーザーのフォルダに入れる。
- Maya は「モジュール」ではなく、ドラッグ＆ドロップでシェルフにボタンを追加する方式（利用者の要望）。Maya 起動時の自動読み込みはしない。
- AE パネルは自己署名した ZXP を配布し、利用者の PC の PlayerDebugMode（レジストリ）を変えない（利用者の選択）。
- サーバーは PyInstaller の onedir（onefile は起動ごとの展開とウイルス対策ソフトの誤検知が増えるため避けた）。

### D-15: ハブ・ランチャー・モニター（2026-10-16、利用者の要望）

- AE と Maya 以外のアプリ、タイムワープ以外のデータにも広げる予定のため、サーバーを「ハブ」として一般化し
  （能力の申告、データ種別レジストリ、アプリ形式 → 中立形式 → アプリ形式の変換）、
  管理用のランチャーとモニターを別プロセスで用意する。詳細は `docs/PLATFORM_DESIGN.md`。
- 利用者の決定: 対応アプリは未定（一般的な仕組みで受ける）、更新の配布元は GitHub Releases（利用者ごとの読み取り専用トークン、
  EXE に埋め込まない）、ランチャーは普通のウィンドウ、順番はモニターから（P-A → P-B → P-C → P-D）。

### D-16: AE のコンプの解像度の枠を Maya のビューに表示する（2026-10-16、利用者の要望）

- 目的: Maya で余白付きでレンダーし、AE で最終サイズに切り出す作業のため、最終の範囲を Maya のビューで確認する。
- 利用者の決定: 枠の位置は **アクティブコンポの幅と高さだけ** を使い、Maya のレンダーがコンプの中央に等倍で置かれている前提。
  描き方は **ビューポートにだけ描くノード**（Python API 2.0 のプラグイン、レンダーされない）。送り方は **AE のパネルのボタン**。
- 流れ: AE `guide.request {comp}` → ハブ（検証して中継、履歴は data_type `comp_guide`）→ Maya `guide.apply.request` → `guide.result`。
  確認ダイアログは出さない（表示用のノードを足すだけで、既存のデータを変えない）。
- 枠の計算は `core/comp_guide.py`（純 Python）。プラグインは描画のたびにカメラとレンダー解像度から求め直すので、カメラの設定や
  解像度を変えても追従する。カメラ空間で枠を求め、カメラの行列でワールドへ移して描く（パン・ズームやオーバースキャンにも追従）。
- ノードは **ワールドに置き**（アウトライナーには出さない）、カメラとは `cameraShape.worldMatrix[0] → guide.cameraMatrix` の接続で結ぶ。
  最初はカメラの子に置いたが、Maya 2023 では、今見ているカメラの子にあるプラグインの描画ノードは描かれなかった（利用者の PC で確認、
  2026-10-16）。接続により、カメラを動かすと枠が再計算され、カメラを消すと枠も描かれなくなる。
- ガイドは表示の補助であり、シーンのデータではない。**ファイルにも undo の履歴にも残さない**（2026-10-16、Maya 2024 の mayapy で確認）。
  - ノードは `setDoNotWrite` で保存されない。ただし枠があるあいだ、Maya は `requires "syncbridge_guide.py"` を書く（H-MY-22）。
    プラグインのない PC やレンダーファームで警告が出ないよう、プラグインが保存の直前に枠を外し、直後に戻す（`MSceneMessage` の
    kBeforeSave / kAfterSave）。3 回保存して、ファイルに SyncBridge の記述がないことを確認した。
  - 枠の作成・削除は undo に記録しない。最初は作成を undo 1 回で消せるようにしていたが、作成が履歴にある状態で保存の前後に
    消して作り直し、そのあと undo すると **Maya 2024 がクラッシュした**（`TsetAttrCmd::undoIt`）。消すときはパネルの「枠を消す」を使う。
    開発ルール 2 の「1 回で undo できること」は元データを変える操作のための決まりで、データを変えないこの枠は対象外とした。
    利用者の他の操作の undo / redo は影響を受けないこと、利用者が undo を無効にしていても状態を変えないことも確認した。
  - シーンを開き直すと枠はなくなる（保存されないため）。AE からもう一度送る。
- P-E（ハブの一般化）の前なので、新しいメッセージの種類として最小限で追加した。P-E ではデータ種別レジストリに移す。
- （2026-10-17、利用者の要望）AE に最終サイズのコンポがあるとは限らないため、Maya のパネルでも幅と高さ（プリセットあり）を
  入れて枠を出せるようにした。同じ `comp_guide.show()` を通る。前回の大きさは Maya の optionVar `syncBridgeGuideSize` に保存。
  枠のラベルは、AE から送ったときだけ「AE コンポ名」を付ける（手入力は「1920x1080 / Maya 2112x1188」）。

### D-17: Maya のシェルフはインストーラーが専用タブとして置く（2026-10-19、利用者の要望）

- 利用者の要望: `Install.bat` だけで、サーバー・AE・Maya のすべてを使える状態にしたい（ドラッグ＆ドロップを不要にする）。
  決定: Maya の **専用タブ「SyncBridge」**。ドラッグ＆ドロップのファイルは予備として残す。
- インストーラーが、Maya 2023 以降で一度起動されたバージョンのユーザー設定フォルダ（`MAYA_APP_DIR`、なければ
  ドキュメント\maya。英語版と `ja_JP`）に `prefs\shelves\shelf_SyncBridge.mel` と `prefs\icons\syncbridge_shelf.png` を置き、
  `install.json` に記録する。アンインストーラーは記録したファイルのうち、SyncBridge の名前のものだけを消す。
- Maya のモジュール（.mod）や `userSetup.py` は使わない（D-14 の利用者の要望、ほかのツールに影響させない）。
- シェルフのファイルは ASCII のみ。ボタンのコマンドは、既定の場所なら `%LOCALAPPDATA%` から SyncBridge の場所を求める
  （ユーザー名に日本語があっても文字化けしない）。
- 既存のシェルフ（Custom など）にボタンを足す方法は取らない: Maya が終了時に読み込み中のシェルフを保存し直すため、
  インストーラーからは確実に書けない。同じ理由で、アンインストールの前に Maya を終了してもらう。

### D-18: AE のタイムリマップのキーを Maya のマーカーにする（2026-10-20、利用者の要望）

- 利用者の決定: 表示は **タイムスライダーのブックマークとビューの重ね表示の両方**、内容は **キーの番号と素材のフレーム**
  （「AE キー 3/8　素材 36f」）、送り方は **AE のパネルのボタン**。**一度送れば、AE を開いていなくても表示される**こと。
- 時間の対応は転送と同じ `jobs.mapping_context()`（Origin frame、レイヤーの開始時間）。マーカーは AE → Maya の転送で
  タイムワープのキーが置かれるフレームと一致する（`core/markers.py`）。
- 流れ: AE `markers.request {export, options}` → ハブ（書き出しとキーの有無を確認して中継、`server/relay.py`）→
  Maya `markers.apply.request` → Maya が自分のシーンの fps で計算して保存。ハブの中継は解像度の枠と共通にした（`RelayToMaya`）。
- **シーンに保存するもの（1 回の取り消しで戻せる）:** network ノード `syncBridgeKeyMarkers` の文字列属性に JSON、
  キーごとのタイムスライダーのブックマーク（Autodesk の `timeSliderBookmark`、目印の属性 `syncBridgeMarker` 付き）。
  どちらも Maya 標準のものなので、SyncBridge のない PC で開いても問題ない（ファイルの `requires` は `timeSliderBookmark` だけ）。
  送り直したときと「マーカーを消す」では、SyncBridge のものだけを置き換える・消す（利用者のブックマークは残す）。
- **表示だけのもの（保存しない、undo に記録しない）:** ビューの左上に 2D で描くプラグインのノード `syncBridgeKeyMarker`。
  今のフレームがキーから半フレーム以内のときだけ表示する。描画のたびに network ノードを名前で読む（接続すると、
  `delete` が上流の network ノードまで消し、送り直すと新しいノードにつながらなかった。mayapy で確認）。
  保存の前後で外して戻す（D-16 と同じ）。シーンを開いたあとは、プラグインの `kAfterOpen` か SyncBridge のパネルを開いたときに
  出し直す。SyncBridge を起動していない Maya では、ブックマークだけが見える（起動処理には手を入れない、D-17）。
- （2026-10-20、利用者の要望）表示は **すべてのビュー** に出す。Maya の既定の「Update View: Active」（`playbackOptions -view`
  が `active`）では、時間を動かすとアクティブなビューだけが描き直されるため、表示する文字が変わったとき（キーに乗った・外れた）
  だけ `timeChanged` の通知から `M3dView.scheduleRefreshAllViews()` で全ビューを描き直す。利用者の設定は変えない。

### D-19: ポート 8765 がほかのプログラムに使われていたら、次の空きポートでハブを起動する（2026-10-20、利用者の決定）

- 実際に起きたこと: 別のプロジェクトのテスト用の Web サーバー（`py -m http.server 8765`）が残っていて、Maya の Connect が
  「port 8765 is used by another program」で止まった（2 回）。
- 決定: `launcher.ensure_server()` は、まず `session.json` のポートで SyncBridge のハブを探し、なければ 8765〜8774 のうち
  最初の空きポートで起動する（途中で SyncBridge のハブが見つかればそれを使う）。クライアント（Maya、AE、モニター）は
  もともと `session.json` からポートを読むので、変更は起動側だけ。
- 8765 を飛ばしたときは、使っているプログラムの名前と PID（`netstat -ano`、`hubs.port_owner()`）を日本語で Maya のパネルに出す。
  10 個とも使えなければ日本語のエラー。

### D-20: 解像度の枠とキーのマーカーを、ビューの「表示」メニューの専用の項目で出し入れする（2026-10-20、利用者の要望）

- 理由: 枠とマーカーはプラグインのロケーター（`MPxLocatorNode`）なので、ロケーターを隠すと一緒に消えていた。
  利用者は作業中にロケーターを隠すことが多い。
- 最初の案（ロケーターのまま `excludeAsLocator()` で「ロケーター」の表示から外す）は、Maya 2025 の GUI で効かなかった
  （テスト用プラグイン、2026-10-20。「ロケーター」を切ると消えた）。
- 決定: 2 つのノードを **プラグインのシェイプ（`MPxSurfaceShape`、`registerShape`）** に変え、`excludeAsPluginShape()` で
  「プラグインのシェイプ」の表示から外し、`pluginDisplayFilter` で「SyncBridge 解像度の枠」「SyncBridge キーのマーカー」を
  ビューの「表示」メニューに登録する（プラグインの読み込み時に登録、解除時に削除）。描画（`MPxDrawOverride`）、属性、
  ノード ID、保存時に取り外す仕組みはそのまま。ノードはシーンに保存されないので、古いシーンとの互換の問題はない。
  同じ方法のテスト用プラグインは Maya 2025 の GUI で、ロケーターを切っても残り、専用の項目でだけ消えた。H-MY-27。

### D-21: シーン設定（FPS・再生範囲・アニメーション範囲・ピクセル縦横比）の転送（2026-10-20、Phase 2、利用者の決定を含む）

- 両方のパネルから、両方向に送れる。項目はチェックで選ぶ（パネルごとに記憶）。変換はハブの `core.scene_sync`（D-2）。
  転送と同じく、転送先で確認ダイアログ → バックアップ → 1 回の取り消しで戻せる適用 → 読み戻し（SPEC 5 章）。
- 時間の対応は転送と同じ「Origin frame（Maya）= AE のコンプの 0 秒」。**AE のコンプの開始フレームも Origin frame にする**
  （利用者の決定。AE と Maya で同じフレーム番号が表示される）。アニメーション範囲 ⇔ コンプ（Origin frame から始まり、
  長さ = 終わり − Origin + 1）、再生範囲 ⇔ ワークエリア。始まりが Origin と違うときは注意を出す。
- Maya の FPS を変えるとき、**キーはフレーム番号のまま**（利用者の決定。`currentUnit -updateAnimation false`）。
  再生範囲は秒で保たれて動くので、FPS のあとで範囲を設定し直す。現在のフレーム番号も保つ。
  Maya が持たない FPS（18、72 など）は日本語で断る。AE の 29.97 と Maya の 29.97fps は同じとみなす（差 0.01 未満）。
- Maya の適用はプラグインの取り消しできるコマンド `syncBridgeApplySettings`（H-MY-28）: Maya 2023 では取り消しのまとまりで
  `playbackOptions` が戻らなかった（mayapy）。コマンドが前の値を持ち、取り消しで全部戻す。中で呼ぶコマンドは記録しない。
- Maya の `pixelAspect` を変えても `deviceAspectRatio` は変わらないので、幅 / 高さ × ピクセル縦横比を一緒に設定する。

### D-22: タイムスライダーの同期（2026-10-20、Phase 2、利用者の決定を含む）

- **双方向**（利用者の決定）。スイッチは 1 つで、どちらのパネルで切り替えても両方に反映（ハブが状態を持ち、接続時にも送る）。
  オンにしたパネルのアプリの時間に、もう片方が合わせる。
- メッセージの時間 `t` は AE のコンプ時間（秒）。Maya が自分の Origin frame と FPS で変換する（`core.time_sync`）。
  ハブは中継だけ（履歴に残さない）。
- Maya → AE: `timeChanged` の通知。スクラブ中は 1 秒に 30 回まで（最後の位置は必ず送る）。**再生中も追従するかは切り替え可能**
  （利用者の決定、既定はオフ: 再生中は送らず、止めた位置を送る）。
- AE → Maya: AE には時間が動いた通知がないので、パネルが 0.05 秒ごとに `comp.time` を読みに行き、変わっていれば送る
  （最初は 0.15 秒。利用者のテストで両方向とも少しラグがあり、2026-10-23 に短くした）。Maya から時間を受け取った直後の
  0.3 秒は読みに行かない（AE の evalScript は 1 つずつ実行されるので、読み取りが時間の設定の前に割り込むと遅れる）。
  Maya → AE の残りの遅れは、主に AE がフレームを描き直す時間（ビューアの解像度を下げると速くなる）。
- 往復の防止: 受け取って動かした時間は、自分の変化として送らない（Maya: `EchoGuard`、AE: 最後に適用した時間と比べる）。
  Maya が再生中は、AE からの時間で動かさない。

### D-23: Pixel Mapping（AE の BG スライドを Maya のカメラで再現）の座標と方式（2026-10-24、Phase 0 / 1）

- 仕様は利用者の「Pixel Mapping / BG Slide Sync 追加開発仕様書 v1.0」。詳細は `docs/PIXEL_MAPPING.md`。
- 共通の座標は **元画像の画素座標**（左上の角が原点、y 下、画素の中心は +0.5、double）。画素ごとの ID は使わない。
  AE は「元画像 → コンプ」の 3 × 3 アフィン行列、Maya は「元画像 → レンダー」をカメラの投影から求めて比べる。
- 変換は `core/pixel_mapping.py`（DCC 非依存、標準ライブラリのみ）、画像の比較は `pixelcheck/`（同期と独立。numpy が
  どの Python にもないので標準ライブラリで PNG を読む）。
- Maya の BG は利用者の制作に合わせて **3D の板ポリ** を基準にする（UV から元画像の角の位置を求める）。
  Image Plane は mayapy の検証で位置が丸められる・ずれるため、基準にしない。
- 方式は 3 つとも実装し、既定は **Film Offset**（透視）。平行投影では Film Offset と 2D Pan がレンダーに効かないので
  **Film Translate**。カメラの Transform とリグは変えない。キー・接続・ロックのある属性は上書きしない。
- 1 px 未満を妨げるのは方式ではなくテクスチャの扱い（Hardware 2.0 のテクスチャの最大解像度、既定 2048）。
  シーンの設定は変えず、利用者に知らせる。

### D-24: Virtual Layer Mapping とハブ経由の BG の位置の転送（2026-10-25、Pixel Mapping Phase 2）

- 対応付けは **Maya のシーン**（network ノード `syncBridgeLayerMappings`、JSON）に保存する。キーのマーカーと同じ方式で、
  シーンと一緒に別の PC へ移る。AE のプロジェクトには書かない（AE のどこに安全に書けるかは未確認のため）。
- AE のレイヤーは **コンプ ID + レイヤー ID**（ID がなければ名前）で、Maya のノードは **UUID** で見分ける。名前、
  インデックス、ネームスペースの変化に強い。
- 値の計算は **Maya の中で core を使う**（キーのマーカーと同じ。カメラと BG の情報は Maya にあるので、往復が 1 回で済む）。
  ハブは AE のデータを確かめて中継するだけ（`PixelMapFlow`）。
- 初回（対応付けを作るとき）だけ確認ダイアログを出す。BG の位置の調整のたびに確認させないため。毎回、バックアップと
  1 回の取り消し、キー・接続・ロックのある属性は上書きしない（開発ルール 2）。
- Phase 2 は今のフレームだけ。アニメーション（Phase 3）では、同じ対応付けでフレームごとに値を求めてキーにする予定。

### D-25: Pixel Mapping の相対モード（3D の BG・カメラワーク対応、2026-10-25、Phase 2.5、利用者の要望）

- 利用者: BG は建物・町並みのモデルのこともあり、カメラワークもある。最終的には AE で 2D の調整をするので、「AE での見え方を
  基準に、Maya でフィルムオフセットを加算すれば再現できる」。
- 決定: 対応付けに **相対モード** を足し、**新しく選ぶときの既定**にする。基準（AE の BG の位置とカメラの値）を最初の送信で
  記録し、以後は AE の BG の 2D の変化（平行移動・拡大縮小）をカメラに足す。BG のモデルは何でもよい（ジオメトリを使わない）。
- 理由: Film Offset / 2D Pan / Film Translate / Zoom はレンズの中心を動かさない 2D の変換なので、どの深さの物も同じだけ動く
  （mayapy で 3 つの深さを確認、0.007 px）。
- 既定の方式は **2D Pan/Zoom**（カメラワークがよく使う Film Offset と別の属性で、拡大縮小も表せる）。カメラワークのキーが
  ある属性は上書きしない（Film Offset 方式は、そのカメラでは断る）。回転は表せないので断る。
- 板ポリに画素まで合わせる D-24 の方式は **絶対モード** として残す。

### D-26: フィルム面の 2D 変換のすべて（Pre / Post Scale、Film Roll）をカメラのモデルに入れ、回転も送る（2026-10-25）

- 利用者: AE で BG を回転・拡大したい。Maya の Pre Scale・Post Scale・Film Roll が使えないか。
- mayapy で順序と単位を測り（H-PM-8）、core のカメラのモデルに入れた。Zoom の位置（Film Translate より前）の誤りも直した。
- ソルバーは、オフセットの式を直接書く方法をやめ、モデルを使って 2 つの値を数値で解く（どの設定のカメラでも正しい）。
- 新しい方式 **「Film Translate・Scale・Roll」**（`film_roll`）: 相対モードで平行移動・拡大縮小・回転のすべてを表す。
  2D Pan/Zoom（既定）は回転を表せないので、回転するカットはこの方式を選ぶ。
- 対応付けの方式はパネルの「方式を変更」で変えられる（相対モードは基準を取り直す。古い基準は前の方式の値なので）。

### D-27: Pixel Mapping の確認は Overscan 1.0 で行う（2026-10-25、利用者の決定）

- Maya は解像度ゲートを表示すると Overscan を 1.3 にし、そのビューポートではゲートの枠に対する BG の位置がレンダーとずれる
  （H-PM-10）。レンダーと余白なしの Playblast（AE に持っていく素材）には Overscan は効かない（H-PM-9）。
- 計算はレンダーと余白なしの Playblast に合わせる（Overscan を無視）。ビューポートの挙動は追わず、Overscan が 1 でないときは
  パネルのログで「解像度ゲートを隠して Overscan を 1.0 に」と促す。

### D-28: レイヤーマップ（AE のレイヤーと SyncBridge の Maya レイヤーをノードでつなぐ）（2026-10-25、利用者の要望）

- 実際のカットは BG だけでなく Book もキャラも複数ある。パネルの「カメラ・BG・方式」1 組では足りないので、
  別ウィンドウのノードエディター（左に AE のレイヤー、右に Maya レイヤー、線 = 接続）にした。
- **Maya レイヤー** = SyncBridge 独自のまとまり（Maya の表示・レンダーレイヤーではない）: 使うカメラと表示するオブジェクト。
  オブジェクトは今は記録と選択だけ（表示の切り替えは後のフェーズ、利用者の決定）。
- 保存形式を schema 2 に（`maya_layers` と `mappings`、各接続に `maya_layer`）。schema 1 のシーンは読み込み時に
  カメラごとの Maya レイヤーへ移す。AE のレイヤーは 1 本の接続だけを持ち、別の Maya レイヤーへつなぐと線が移る
  （基準は消す）。Maya レイヤーのカメラを変えると、つながる接続の基準も消す（古いカメラの値だから）。
- AE のレイヤー一覧は Maya から取りに行く（`layers.request` → ハブ → AE の `layers.export.request`）。履歴には残さない。
- 画面（`layer_map_view.py`）は Maya を import しない Qt だけの部品にし、Maya とのやり取りは `layer_map_window.py` に分けた
  （`.venv` の PySide6 でモックとテストができる）。変更は 1 回ずつ undo チャンクにし、undo・シーンの切り替え・AE からの
  送信のあとに読み直す。
- **設定はレイヤーマップに一本化**（利用者の指摘: パネルにも設定があると、どちらで決めるのか分からない）。パネルの Pixel Mapping 欄は
  接続の数と「レイヤーマップを開く…」だけ。つないでいない AE のレイヤーが送られたら、カメラを変えずに断って案内する
  （利用者の決定。以前はパネルのカメラ・方式で自動でつないでいた）。新しい接続は相対モードで、方式はレイヤーマップの
  ツールバーで選ぶ。絶対モードへは線ごとに、Maya で板ポリを選んでから切り替える。

### D-29: Maya レイヤーごとの専用カメラ（2026-10-25、利用者の決定）

- BG とキャラが同じカメラを使っていても、AE ではレイヤーごとに別々に動く。1 つのカメラのアトリビュートにはカーブを 1 本しか
  つなげず、1 台のカメラの映像は 1 つの見え方しか持てないので、別々の動きを**同時に**再生するにはカメラを分けるしかない。
- 検討した案: (1) Maya のアニメーションレイヤー / Blender の Action のようにカーブの組を付け替える → 同時には再生できず、
  書き出しのたびに切り替えが要る。(2) Maya レイヤーごとに、元のカメラの子として専用カメラを作る → 採用。
- 専用カメラ `SB_<レイヤー名>_CAM` は元のカメラのトランスフォームの子で、移動・回転・拡大縮小は 0 / 1 のままロック
  （カメラワークは元のカメラだけで直せる）。焦点距離・フィルムバック・クリップ・Shake は元のシェイプからつなぐ。
  SyncBridge が動かす 2D の値（Film Offset / Film Translate / Pan/Zoom / Pre・Post Scale / Roll、Overscan）は専用カメラが持ち、
  作るときに元の値を写す。元のカメラのこれらにキーがあると、その動きは専用カメラに入らないので注意を出す（足し合わせは今後）。
- 接続が動かすのは専用カメラ（`core.layer_mapping.driven_camera`）。schema 1 から移したレイヤーには専用カメラがなく、
  今までどおり元のカメラを動かす。Maya レイヤーの削除は専用カメラも消す（確認あり、1 回の undo で戻る）。
- mayapy 2023 / 2024 で確認（`tools/pixel_mapping/maya_layer_camera_check.py`）: 各フレームでワールド行列とレンズの差 0、
  Hardware 2.0 のレンダーの差 0（H-MY-30）。同じカメラの BG と CHAR に別々に送ると、それぞれの専用カメラだけが動く。

### D-30: Phase 3 アニメーションの転送は「各フレームの 1 回送信」をキーにする（2026-10-25）

- レイヤーマップで線を選び「アニメーションを転送…」→ Maya のフレーム範囲と Origin frame（時間の同期と同じ。
  AE のコンプ時間 = (フレーム − Origin) ÷ fps）→ Maya が AE に各フレームの時間でのトランスフォームを問い合わせる
  （`motion.request`、ハブ経由、履歴には残さない）→ フレームごとに 1 回送信と同じ式で解く（`core.motion`）→ 確認 →
  JSON バックアップ → 1 回の undo でキー → 読み戻し。
- キーは 1 フレームに 1 個、リニア。AE のキーの形（ベジェ・ホールド）は写さず、フレームの値で合わせる
  （精度を優先。フレームの間の値は直線で補う。モーションブラーで差が出うる）。スイッチ（Pan/Zoom の有効など）はキーにせず値を設定。
- 範囲内の既存のキーは置き換え、範囲外は残す。アニメーションカーブ以外がつながったアトリビュートやロックは断る。
- 相対モードは先に基準が要る（1 回送信で記録）。基準のない接続はキーを打たずに案内する。絶対モードの BG の板ポリは
  今のフレームの位置で読む（BG が動く場合は未対応）。
- 計算はすべて core（標準ライブラリのみ）。カメラの各フレームの値は `getAttr -time` で読む（H-MY-31）。
- **すべての接続を 1 ボタンで**（利用者の要望: 線ごとの操作は手間）。ツールバーの「すべてのアニメーションを転送…」は、
  範囲の指定 1 回 → AE への問い合わせを接続ごとに順に → 確認 1 回 → キーは 1 回の undo にまとめる（バックアップは接続ごと）。
  無効の接続・基準のない相対の接続・AE で見つからないレイヤー・解けないフレームのある接続は飛ばし、確認と結果に理由を出す。

### D-31: Maya レイヤーの表示はビューだけで切り替える（2026-10-25、利用者の決定）

- 「このレイヤーで見る」（ノードのダブルクリックでも）で、今のビューをそのレイヤーのカメラ（専用カメラ）にし、
  表示するオブジェクトだけを Isolate Select で見せる。「表示を戻す」で Isolate Select を切る（カメラはそのまま）。
- シーンの値（visibility、表示レイヤー、レンダーセットアップ）は変えない。検討した表示レイヤー案は利用者の表示レイヤーと混ざり、
  レンダーセットアップ案は仕組みが大きく既存の設定とぶつかりうるので見送り。Playblast には効くがレンダーには効かない。
- Isolate Select はビューの機能なので mayapy では確かめられない（H-MY-32、GUI で確認）。

### D-32: レイヤーを重ねて見るビュー（Viewport 2.0 のレンダーオーバーライド、試作、2026-10-25）

- 利用者の要望: BG とキャラは別の素材として出し、それぞれスライドやカメラの Pan をするので、AE のように重ねて見る専用のビューが要る。
  普通のビューはカメラを 1 台しか使えないので、レイヤーごとに別のカメラで描いて重ねる仕組みが要る。
- 案 1（採用、試作）: Viewport 2.0 のレンダーオーバーライド（`plug-ins/syncbridge_layer_stack.py`）。Maya レイヤーごとに
  `MSceneRender`（カメラ = 専用カメラ、オブジェクト = 表示するオブジェクト）を 1 本、下のレイヤーから順に描く。1 本目は全部を消し、
  2 本目からは奥行きだけを消すので、上のレイヤーは奥行きに関係なく下のレイヤーの上に乗る（AE の重ね方）。ビューそのものなので
  再生・スクラブに追従し、Playblast にも写るはず。案 2（別ウィンドウでレイヤーごとの画像を重ねる）は試作がだめだったときの代わり。
- 順番はレイヤーマップの Maya レイヤーの並び（上にあるほど手前）。カメラか表示するオブジェクトのないレイヤーは描かない。
- レイヤーの一覧は `syncbridge_maya.layer_stack.publish()` が `__main__` 経由でプラグインに渡す（SB Dev でスクリプトを読み直しても
  プラグインは読み直されないため）。レイヤーマップの変更・undo のあとに渡し直す。

### D-34: ビューアーの枠はフィルムバック・Film Fit・Overscan だけで置く（2026-10-25）

- 最初は D-16 の計算（カメラ空間の枠）をビューの表示行列で画面に投影したが、表示行列には元のカメラの Film Translate などが入るので、
  元のカメラの Film Translate を変えると枠も動いた（利用者の指摘）。各レイヤーは専用カメラで描くので、レイヤーは動かずに枠だけがずれる。
- 枠は「コンポ（レンダー）の範囲」なので、絵をずらす値（Film Offset / Pan・Zoom / Film Translate / Scale / Roll）には関係しない。
  `core.view_frame.frame_rect` が、フィルムバック・Film Fit・Overscan・レンダーの縦横比だけからビュー上の位置を出す
  （コンポがレンダーより小さければ中央にその割合で）。mayapy 2023 / 2024 で、カメラに Film Translate・Film Offset・Pan を入れた
  場合も含め、Maya の `getViewingFrustum` / `getRenderingFrustum` と 384 通りで最大 0.000001 px。
- 枠の外側は半透明の黒で暗くする（解像度ゲートの外側と同じ見え方、利用者の要望）。
  濃さはビューアーの「枠の外」スライダーで 0〜100%（既定 50%、optionVar `syncBridgeViewerShade`、利用者の要望 2026-10-27）。
  `layer_stack.publish` が `"shade"` としてプラグインに渡す（プラグイン r10）。0% のときは暗くする帯を描かない。

### D-46: Maya / AE のパネルから更新する（About）（2026-10-28、利用者の決定。**一時的な形で、今後変わりうる**）

  - ExtendScript の `system.callSystem` を使う案: AE の「スクリプトによるファイルへの書き込みとネットワークへのアクセス」の設定に左右されるため。
- 未確認: H-AE-19（実際の AE で Node が使えるか）、H-UPD-1（Maya / AE を開いたままの更新）。

### D-44: ビューアーの編集中レイヤーと 2D パン・ズーム（2026-10-27、利用者の決定）

- 背景: ビューアーは各レイヤーをそれぞれのカメラ（素材カメラ・専用カメラ）で描くが、Maya のクリック選択・マニピュレーターは
  パネルのカメラ 1 つで計算するので、ほかのカメラのレイヤーは見た位置で選べず動かせなかった。余白の縮小もずれの元だった。
  利用者は、ビューアーでズームしながらキャラや BG の動きを調整したい（2D Pan/Zoom は Maya と同じ操作感で）。
- 決定:
  - **編集中のレイヤー**を 1 つ持つ。ビューアーのパネルは、その専用カメラの子の **SB ビューカメラ**（`viewer_camera.py`）を通して
    見る。レンズ・フィルムバック・Film Translate・Post Scale・Roll は専用カメラからつなぎ、専用カメラの 2D Pan/Zoom は
    Film Offset と Pre Scale に折り込む（`core.stack_view.fold_pan_zoom` と同じ式をユーティリティノードで。キーも追従）。
    ビューカメラ自身の Pan/Zoom はビュー用に空いているので、Maya の 2D Pan/Zoom ツールがそのまま使える。
    編集中のレイヤーでは Maya 標準の選択・移動・キーの操作が見た目どおりに効く（H-MY-38）。
  - ほかのレイヤーと枠は、プラグインが同じ見え方の変化（`view_affine` = 編集中のカメラの NDC → ビューカメラの NDC）を
    掛けて描く（プラグイン r11）。編集中は、余白はプラグインの縮小ではなくビューカメラの Zoom の初期値になる
    （余白を選ぶ・「ズームを戻す」で Pan 0・Zoom = 余白）。
  - **クリックで切り替え**: 編集中でないレイヤーのメッシュをクリックすると、そのレイヤーを編集中にしてそのオブジェクトを選ぶ。
    判定はレイヤーのカメラからの光線とメッシュの交差（`viewer_pick.py`、H-MY-39）。マウスは常に Maya に渡し、
    押した位置のまま離したとき（4 px 以内）だけ、Maya の選択が済んだ後で切り替える。ドラッグ（マニピュレーター・範囲選択）は触らない。
    クリックの前後で選択が変わらず、選択中のメッシュもカーソルの下にないときは、マニピュレーターのクリックとみなして切り替えない。
    編集中のレイヤーに当たったとき、何にも当たらないときも切り替えない。一覧の行のクリックでも切り替える。
    修飾キーは Maya のクリックと同じ意味に合わせる（2026-10-28、P-4）。

    | 操作 | 動き |
    |---|---|
    | 修飾キーなし | 置き換え |
    | Shift | トグル。押す前から選ばれていたものは外し、編集中は替えない |
    | Ctrl+Shift | 追加 |
    | Ctrl だけ・Alt つき | 触らない |

    以前は Shift を追加として扱い、ほかのレイヤーのものを Shift のクリックで外せなかった。
  - **選択を変えない**（2026-10-28、P-11）: ビューカメラを作る・移す・消すときは、選択を取っておいて、順番ごと戻す（undo には積まない）。
    `parent`・`camera`・`createNode` が作った・移したノードを選ぶため（H-MY-44）。
    以前は、一覧の行のクリック・Shift のクリック・レイヤーの削除で、選択が `SB_VIEWER_CAM` や計算用のノードに置き換わった。
  - **非表示のレイヤーは編集中にしない**（2026-10-28、P-5）: 編集中のレイヤーが非表示になったら、表示中の一番上のレイヤーへ移す。
    非表示の行のクリックでは切り替えず、知らせる。描かれていないレイヤーの視点で、Maya の選択・移動が動いてしまうため。
  - **描かれていないものは選ばせない**（2026-10-28、P-1）: Maya の選択は、パネルのカメラから見たシーンのすべてのものを対象にする（H-MY-44）。
    そのため、描かれていないものまで選ばれてしまう。
    - 対象: ほかのレイヤーのもの（ビューカメラで見たときの位置にある）、未登録のもの、非表示のレイヤーのもの。
    - 方式: ビューアーの中で左ボタンを離したら（クリックでも囲みでも）、Maya の選択の後で、編集中のレイヤーと関係ないものを外す。
      - 外すもの: Maya が新しく選んだもの。
      - 戻すもの: Shift / Ctrl で Maya が外したもの。
      - 「関係ある」とは、登録ノード・その子・その親のこと（`core.layer_mapping.related`）。親を含めるのは、階層選択で親が選ばれるため。
    - この補正は undo に積まない。Ctrl+Z 1 回で、Maya のクリックごと戻る。
    - アウトライナーなどビューアーの外での選択は触らない。
    - ビューアーのパネルの Isolate Select は採らなかった。選択は絞れるが、オーバーライドの各パスも絞られ、ほかのレイヤーが描かれなくなる（H-MY-45）。
  - **カーブ・ロケーターも当てる**（2026-10-28、P-7）: ほかのレイヤーのクリックの判定に、NURBS カーブ（描かれた線から 6px）と
    ロケーター（中心から 10px）を加える。光線ではメッシュにしか当たらないため。同じレイヤーの中ではメッシュより優先する。
    リグのコントローラーは体に重ねて置かれるため。
  - **選択に合わせて切り替える**（2026-10-28、9.5。外部のレビューの意見を受けて Claude が判断）:
    ビューアーが開いている間は、選択の変化（`SelectionChanged`）を見る。
    - 選択がすべて 1 つの表示中のレイヤーに属するなら、そのレイヤーを編集中にする。アウトライナー・ほかのビュー・Undo のどれで選んでも同じ。
    - 混ざった選択、描かれていないものを含む選択、空の選択では、カメラを保つ。マニピュレーターが合わないときは、状態の行で知らせる。
      1 台のカメラでは、すべてのレイヤーの見た目とマニピュレーターを合わせられないため。
    - 判定は `core.layer_mapping.selection_layers`。
    - 選択が前回から変わったときだけ切り替える。ビューカメラを動かした後で選択を戻す処理と、一覧の行で選んだ編集中のレイヤーを守るため。
    - オフにする設定は、使ってみて要るなら足す。
  - 選択とカメラの切り替えの残りの課題（選べない設定のもの P-6、透明な部分 P-8）と、
    その方針は `docs/VIEWER_CAMERA_SELECTION_AUDIT.md` の 9 章。
    以前は押した時点でクリックを取り、選択中のもののピボットから 60 px 以内だけ Maya に渡していた。移動の矢印の先（約 100 px）を
    つかむと、その下の別レイヤーに切り替わって選択が外れた（利用者、2026-10-27）。
  - ビューカメラとユーティリティノードは保存しない（`doNotWrite`）、取り消しの履歴に入れない、ビューアーを閉じると消す。
  - **2D Pan/Zoom の ON/OFF**（2026-10-27）: 余白なし（Pan 0・Zoom 1）のときは OFF にする。
    Pan/Zoom の値が変わったら、scriptJob で ON/OFF を合わせる（`panZoom` は ON にしない、H-MY-43）。
  - **ビューアーの枠**（2026-10-27）: 「解像度の枠」は Maya のレンダー設定の解像度を、プラグインが描くたびに読む。
    AE と接続していなくても合うようにするため（利用者）。オン/オフは optionVar に持つ。
    「任意の枠」は、入力した大きさの枠を別の色で中央に描く。AE のメインのコンポが絵より広いことがあるため。
    パネルの「解像度の枠」で作る comp guide ノードは、ビューアーには描かない。
    以前は描いていたが、大きさがパネルで最後に入力した値だったので、数値が合わず、ボタンで消せなかった。
  - **ゲートは使わない**: ビューカメラの解像度ゲート・フィルムゲートが ON になったら、scriptJob ですぐ OFF にし、Overscan を 1.0 に戻して警告する。
    ゲートは Overscan を 1.3 にするので、レイヤーが枠からずれるため（D-34）。
  - 編集中のレイヤーを替えるときは、ビューカメラを作り直さず、新しい専用カメラの子へ移してつなぎ直す。
    ビューカメラの移動・プラグインへの受け渡し・パネルのカメラの設定は、次の描画より前にまとめて行う。
    消して作り直していたときは、遅らせた再描画までの数フレーム、存在しないカメラで描かれてチラついた（利用者、2026-10-27）。
  - 編集中のレイヤーを替えても、見え方（`view_affine`）は変えない。新しいカメラで同じ見え方になる Pan/Zoom を
    `core.stack_view.match_view` で求めて、ビューカメラに入れる。同じ Pan/Zoom の数値でも、カメラのフィルムバック・
    Film Translate・Scale によって効き方が違うので、数値をそのまま引き継ぐと少しずれていた（利用者、2026-10-27）。
  - ビューカメラの `orthographic` はつながず、値を写す。移動のときにつなぎ直すと、パネルのカメラの設定中に
    Maya 2024 が落ちた。パネルのカメラは、パスではなくノード（UUID）で比べて、同じなら設定し直さない。
  - マニピュレーターは最後の 1 パスだけで描く（プラグイン r13、H-MY-42 ✅）。
    - レイヤーのパスは `objectTypeExclusions` で `kExcludeManipulators` を返す。
    - 最後のパスは、マニピュレーター以外をすべて除き、ビューカメラ（Maya が選択・ドラッグに使うカメラ）で、深度を消してから描く。
    - 以前は各パスがそれぞれのカメラでマニピュレーターを描いた。そのため複数見え、ドラッグできるのはそのうち 1 つだけで、
      上のレイヤーに隠れることもあった（利用者、2026-10-27）。
    - r12 の `renderFilterOverride` は、`kRenderNonShadedItems` が UI を含むので効かなかった。
    - 戻り値は C long（Windows では 32 ビット）に収まるフラグだけで作る。
- 制限: 判定はメッシュだけ（リグのコントローラーのカーブは、そのレイヤーを編集中にしてから Maya の選択で）。
  編集中のカメラに Film Translate があると、ズームの中心は Maya の 2D Pan/Zoom と同じくその分ずれた位置になる。

### D-43: AE のレイヤーをマップに追加すると、つないだ Maya レイヤーを 1 つずつ作る（2026-10-27、利用者の決定）

- 背景: これまでは AE のレイヤーを追加 → Maya レイヤーを追加 → カメラ・オブジェクトを設定 → 線でつなぐ、と手順が多かった。
  利用者の使い方では AE のレイヤーと Maya レイヤーは必ず 1 対 1。
- 決定: レイヤーマップの「AE の選択を追加」で、まだつながっていない AE のレイヤーごとに、同じ名前の Maya レイヤーを作って
  つなぐ（`core.layer_mapping.add_linked_layer`、Maya では `layer_mapping.add_ae_layers`、全体で取り消し 1 回）。
  接続は **素材カメラのモード（D-39）・Film Translate・Scale・Roll**（`film_roll`）で固定。最初は Film Translate に
  していたが、利用者の意図は Film Translate・Scale・Roll だった（2026-10-27）。Film Translate は平行移動だけなので、
  コンポより広いプレート（横 3 倍の BG / BOOK）は拡大縮小が表せず、AE と一致しなかった。手で線をつなぐときも同じ（ツールバーの「新しい接続」の
  選択欄は外した、利用者の指示）。モードと方式は、線を選んで右の欄から線ごとに変えられる。
  同じ名前でまだつながっていない Maya レイヤー（手で作ったもの、テストシーンが作ったもの）があれば、作らずにそれにつなぐ。
  素材カメラのモードは、カメラ未設定の Maya レイヤーにも手でつなげる（相対・絶対はカメラが要る）。
- カメラとオブジェクトは利用者が手で設定する（右の欄の「選択中のカメラにする」で専用カメラができ、接続もそれに付く）。
  カメラが未設定の間は、接続の `maya.camera_uuid` が空（`new_mapping(camera_required=False)`）。
  - アニメーション転送・リアルタイム同期（`motion.transferable`）、1 回の送信（`pixel_mapping`）、1 本の転送は、
    「カメラがまだ設定されていません」と理由を出して飛ばす。同じカメラの重複の警告（`camera_conflicts`）からも外す。
  - マップのノードは「⚠ カメラ未設定」、接続の説明は「カメラ未設定」。
- すでにつながっている AE のレイヤーには何も作らない。「AE のレイヤーを読み込む」（メインのコンポの読み直し）では作らない。

### D-42: Maya パネルをタブに、AE パネルを並べ替える（2026-10-27、利用者の決定）

- 背景: UI/UX の現状調査（`docs/UI_UX_AUDIT.md`）で、Maya パネルは縦に長くスクロールが要り、状態が文字の 2 行に分かれ、
  あまり触らない Mode・Tolerance が一番上にあった。AE パネルも機能が順不同に並び、ボタン名が英語と日本語で混ざっていた。
- 決定（モック `docs/ui_audit/proposal/` を利用者が確認）:
  - 両方とも、上に状態（● サーバー・相手のアプリ・タイムスライダー同期・リアルタイム同期）、その下に Origin frame。
  - Maya パネルはタブ 4 つ「タイムワープ / 同期・設定 / レイヤー / その他」（「その他」は漢字、利用者の指示）。開いていたタブは
    optionVar `syncBridgePanelTab` に覚える。レイヤーのタブにリアルタイム同期のスイッチと「すべてのアニメーションを転送…」を置く
    （レイヤーマップ・ビューアーと同じ部品 `make_live_check`・`MotionTransfer`）。
  - Mode・Tolerance は「詳細」にしまう（利用者: Mode はほぼ触らない）。値は折りたたんだ見出しに出す。
  - AE パネルは 選択中のレイヤー → タイムワープ → Maya へ送る → 同期 → シーン設定 の順。パネルの既定の高さを 680 に。
  - AE の「BG の位置を Maya のカメラへ」は、相対モードでは実質は基準の設定なので「レイヤーの初期位置を Maya へ」にする（利用者の指示）。
  - ボタンの矢印は、そのパネルから見た向き（Maya パネル: 「AE へ →」「← AE から」、AE パネル: 「← Maya から」「Maya へ →」）。
  - ログや状態の文も日本語に揃える。
- 変えていないもの: 通信のメッセージ（プロトコル）、転送の手順、確認ダイアログ（パネルの見た目・並び・文言だけの変更）。

### D-41: AE のレイヤー → Maya のリアルタイム同期（2026-10-26、利用者の決定）

- **何を:** レイヤーマップでつないだ AE のレイヤーの位置・キー（親のヌル・プリコンポを含む）を AE で変え終えると、Maya が再生範囲の
  動きを読み直し（Phase 3 の `motion.request` と同じ）、接続の専用カメラのキーを確認なしで更新する。反映は「操作し終えたら」
  （利用者の選択。ドラッグ中は追わない）。方向は AE → Maya だけ。
- **スイッチ:** タイムスライダーの同期（D-22）と同じく 1 つを共有（`live.sync`、ハブが状態と見張るレイヤーを持ち、あとから
  つないだアプリにも送る）。レイヤーマップ・ビューアー・AE のパネルのどれでも切り替えられる。
- **AE での検出:** AE には変更の通知がないので、パネルが 0.4 秒ごとに見張るレイヤーの「指紋」（`layersFingerprint`: 変換の
  プロパティのキーの時間・値・補間・イーズ・空間の接線、キーがなければ値、エクスプレッションの文、親とプリコンポのレイヤー
  と時間）を読み、変わったあと次の読み取りで同じなら（= 操作が終わった）`live.changed` を送る。時間で値をサンプルしない
  （時間に依存するエクスプレッションが、時間の移動のたびに変わったように見えるため）。
- **Maya での反映（`live_sync.py`）:** 見張るレイヤー = 転送できる接続の AE のレイヤー（`live.watch`、レイヤーマップが変わるたび）。
  受け取ったら接続ごとに順に、読み直し → 解く → キー（`motion.apply_all(confirm=False)`、1 回ごとに 1 回の undo
  「SyncBridge live」）。バックアップはスイッチをオンにしてから接続ごとに最初の 1 回だけ（毎回だと大量になるため）。
- **競合（禁止事項「競合時に自動で上書きしない」）:** リアルタイム同期が最後に書いたキーと、今の専用カメラの値が違えば
  （Maya での編集、Ctrl+Z）、その接続は上書きせずに知らせる。スイッチをオンにし直すと、AE の状態で上書きする。
- 見張るのに使う AE の API（キーとイーズの読み取り）と、0.4 秒ごとの読み取りの負荷は未確認（H-AE-34）。

### D-40: レイヤーマップに出す AE のレイヤーを AE の選択で決める（2026-10-26、利用者の決定）

- 実際のコンポにはスライドに関係ないレイヤー（エフェクト、テキスト、調整レイヤーなど）が大量にあり、すべてをノードにすると
  マップが使えない。**マップに出すのは「マップに出した AE のレイヤー」（シーンの `ae_shown`）とつないだもの**だけにする。
  つなぐと `ae_shown` にも入るので、接続を外してもマップに残る。「マップから外す」（Delete）で外す（つないだものは外せない）。
- 出し方は「AE の選択を追加」: AE で BG やキャラを選んで押す。プリコンポの中の BG を選ぶには AE でそのプリコンポを開くので、
  アクティブなコンプを基準にすると外側のコンポ（PAN）が抜ける。そこで**レイヤーマップのメインのコンプ**（マップの AE のレイヤーの
  いちばん外のコンプ、なければ最後に読んだコンプ）を AE に渡し、AE はメインのコンプから中をたどって一覧を返す。各レイヤーの
  `selected` は「AE で開いているコンプでの選択」だけ（ほかのコンプに残った選択は使わない、H-AE-32）。開いているプリコンポが
  メインの中で 2 か所以上に使われていれば経路ごとに追加して知らせる。メインの中にない（4 段以上深い）ときは断る。
- **メインのコンポはシーンに記録する（`main_comp`）。** 最初の実装はマップの AE のレイヤーの外側のコンポから推測していたが、
  プリコンポ（外側のコンポで PAN のために動かしている）を開いたままつないだ接続があると、そのプリコンポをメインと思い込み、
  PAN の分だけずれた（利用者、2026-10-26）。「AE のレイヤーを読み込む」で **AE で開いているコンポをメインにする**（いちばん外の
  コンポを開いて押す）。そのとき、メインの中のコンポを基準に記録された接続・レイヤーを見つけたら、確認してメインからの経路に直す
  （相対モードは基準を記録し直す。経路が複数・見つからないものは警告だけ）。メインの外で記録されたノードと、転送の確認に警告を出す。
- 読み込んだコンポがほかのコンポのプリコンポなら（`usedIn`、H-AE-33）、外側のコンポをメインにするか確認する（AE が「開いているコンポ」と
  みなすものが利用者の意図と違うことがある）。AE からメインと違うコンポが返ったら（古いハブ・パネルはメインの指定を捨てる）何も変えずに断る。
- 「コンポのすべてのレイヤー」のチェックで、出していないレイヤーも薄く一時的に表示できる（線でつなぐとマップに残る）。
- 保存形式は schema 2 のまま `ae_shown` を足した（古い版は読み飛ばす）。追加・外すはそれぞれ 1 回の取り消しで戻る。

### D-39: 素材カメラモード（2026-10-25、利用者の要望）

- 大判の BG は、引いたりレンズを変えたりした BG 用のカメラで書き出す。相対モードでショットのカメラを使うと、基準のときに見え方を
  手で合わせる必要があり、BG 用のカメラの位置が違えば立体の BG の見え方（視差）も少し違う。
- **素材カメラモード:** Maya レイヤーのカメラ = AE の素材を書き出したカメラ（専用カメラはその子、D-29）。AE から素材の大きさ
  （= 書き出した解像度）と、素材 → コンポの行列 M が届くので、基準なしで毎フレーム直接解ける:
  `C = 余白のずらし · M · A(素材カメラ, 素材の大きさ) · A(素材カメラ, 今のレンダー解像度)⁻¹`（A は `camera_affine`: カメラ空間の
  (x/−z, y/−z) → ピクセルのアフィン）。C を `solve_relative`（基準 = 単位行列）に渡して専用カメラの値にする（`pixel_mapping.solve_source`）。
  拡大縮小があるので方式は 2D Pan/Zoom か Film Translate・Scale・Roll。回転は後者だけ。
- 1 回送信・アニメーションの転送・まとめての転送のどれも使える。基準の記録は不要（「基準を記録」は断る）。新しい接続のモードを
  レイヤーマップのツールバーで選ぶ（素材カメラ / 相対）。相対モードは素材を撮ったカメラが分からないときのために残す。
- mayapy 2023 / 2024（`tools/pixel_mapping/maya_source_camera_check.py`）: フィルムバック 3 倍の大判用カメラで 1920×1080 の大判を書き出し、
  AE で 100% のまま整数 px ずらした 640×360 のコンポの見え方（大判の切り抜き）と、素材カメラモードの専用カメラのレンダーが、
  3 通りとも**ピクセル単位で完全に一致**（差 0）。奥行きの違う箱で視差も確認。

### D-38: Origin frame と範囲をツールで 1 つにする（2026-10-25、利用者の決定）

- これまでは Maya のパネル（開くたびに再生範囲の開始で初期化、保存なし）と AE のパネル（AE 側だけに保存）に別々の Origin frame があり、
  どちらから送ったかで結果が変わりえた。
- **Origin frame は Maya のシーンに 1 つ**（`network` ノード `syncBridgeTiming.originFrame`、`syncbridge_maya/timing.py`）。一度も
  決めていなければ再生範囲の開始。undo には残さない（パネルとハブがその値のままになるため）。
- ハブは `timing.set {origin}` を受けて覚え、全員に `timing.state {origin, by}` を配る（あとから接続した側にも）。Maya は接続したときと
  シーンを開いたときに自分の値を送り、AE からの変更はシーンに保存する。AE のパネルの入力欄はその値を表示し、変えれば Maya に届く。
- 時間の同期・タイムワープの転送・マーカー・設定の転送・レイヤーマップ（基準の記録・アニメーションの転送）は、すべてこの値を使う。
- **範囲は Maya の再生範囲**（利用者の決定）。アニメーションの転送のダイアログは再生範囲を初期値にし、Origin frame は入力をやめて表示だけ。

### D-37: プリコンポごと動かす PAN と、基準のカメラは規定値（2026-10-25、利用者の要望）

- AE のレイヤーの一覧に、プリコンポの中のレイヤーも 3 段まで出す（`via` = 上にあるプリコンポのレイヤーの道筋）。レイヤーマップでは
  「SC_PRE › BG」と字下げして並べ、直接つなげる。接続は自分のコンポと `via` を持ち、同じプリコンポが 2 か所で使われても区別する。
- AE は道筋をたどり、各時間で外のプリコンポのレイヤー（とその親）の変換を返し、中の時間は `sourceTime` で求める（H-AE-31）。
  core は「外のプリコンポのレイヤー × … × 中のレイヤー（それぞれ親を含む）」で掛ける。3D のものは断る。
- AE のパネルの「BG の位置を Maya のカメラへ」は選んだレイヤーしか分からず、外での動きを送れない。プリコンポの中のレイヤーは
  Maya のレイヤーマップで「基準を記録（今のフレーム）」（Maya の今のフレームで AE に問い合わせる。どの接続にも使える）と
  「アニメーションを転送」で使い、パネルから送られたら案内して断る。
- **基準のカメラの値は規定値**（利用者: 基準を取るとき、すでにアニメーションを付けたあとかもしれない）: 専用カメラの今の値
  （前の転送のキー）ではなく、専用カメラのもとの値 = 元のカメラの値（SyncBridge は元のカメラを動かさない）を使う
  （`pixel_mapping.base_values`）。専用カメラのない古い接続は Maya の既定値。カメラそのものは変えない。

### D-36: PAN（ヌルの親）と、余白付きのレンダー（2026-10-25、利用者の指摘）

- **PAN:** 利用者は画面全体の PAN を (1) ヌルの親、(2) プリコンポごと、(3) AE のカメラレイヤー で付ける。まず (1): AE が親を順に
  たどって各時間の変換を返し（`parents`、`pixelMapInfo` と `layerMotion`）、core が AE と同じ順（親の変換 × 子の変換、H-AE-30）に
  掛けてコンポ上の行列にする。3D の親は (3) のときまで断る。(2) (3) はこのあと。
- **レンダー解像度 ≠ コンポ:** 余白を出すために、Maya のレンダー解像度が AE のコンポより大きいことがある。解像度の枠（D-16）と同じく、
  コンポはレンダーの中央、画素の大きさは同じと見なし（`pixel_mapping.to_render_space`）、AE の行列を余白の分ずらしてレンダーの画素で
  解く。相対モードの基準もレンダーの画素で持つ（これまで両者は同じ大きさに限っていたので、前の基準はそのまま使える）。
- mayapy 2023 / 2024（`tools/pixel_mapping/maya_pan_margin_check.py`）: レンダー 2112×1188・コンポ 1920×1080 で、自分の位置で動かしても
  ヌルの親で動かしても、レンダー上でちょうど 80 / −30 px 動く。

### D-35: ビューアーの余白はビューアーの中だけで縮める（2026-10-25、利用者の決定）

- 要望: 枠を表示しているとき、少し縮小して枠のまわりを見たい。Overscan では Maya のビューが 2D のずらしを縮めないのでずれた（D-33）。
  カメラの値を変える方式は普通のビューや Playblast にも効くので採らない。
- 余白が有効なとき（枠を表示中）、プラグインは各レイヤーの描画の投影を自分で組む: `core.stack_view.ndc_affine` が、レンダーで検証済みの
  カメラの式（`core.pixel_mapping.project`。Film Offset・Pan/Zoom・Pre/Post Scale・Roll・Film Translate）から、カメラ空間 `(x/-z, y/-z)` →
  ビューの NDC のアフィンを作り、絵全体を中心から 1/余白 に縮める。`projection_rows` がそれを 4×4 の投影にし、奥行きと w の列は
  Maya が実際に使っている投影（HUD の段で写し取る）を使う。枠も `view_frame` で同じ割合だけ縮める。
- 余白はビューアーの「余白」で なし・10%・20%・30%（既定 20%、optionVar `syncBridgeViewerMargin`）。カメラの値は変えない。
- 余白なしのときは Maya の普通の投影のまま。平行投影のカメラは縮めない（注意を出す）。
- mayapy 2023 / 2024（`tools/pixel_mapping/maya_stack_margin_check.py`）: 余白 1.0 で Maya の視野（Film Offset・Pan・Zoom、4 種類の
  Film Fit）と 128 通りで最大 0.0008 px、余白 1.2 でちょうど 1/1.2。Film Translate・Scale・Roll は Maya の視野の関数に入らないので
  GUI で確かめる（H-MY-37）。
- **Overscan:** 一度は専用カメラの Overscan を元のカメラからつないだが、利用者が元のカメラを 1.2 にすると、レイヤーと枠は両方
  縮んだのに位置がずれた（2026-10-25）。Maya のビューは Film Translate / Pan / Offset の分を Overscan で縮めないため
  （H-PM-10 と同じ原因と考えている）。→ **専用カメラの Overscan は常に 1.0（つながない）**、ビューアーの枠も 1.0 として置く。
  元のカメラの Overscan（普通のビューで解像度ゲートを出すと 1.3）はビューアーにも「このレイヤーで見る」にも届かない。
  前の版の専用カメラは、ビューアーを開いたときに直す（つなぎを外して 1.0、1 回の undo）。
- **レイヤーごとの解像度（BG は大判、キャラはフル HD など）:** 利用者の回答（2026-10-25）は「大判の出し方は (a) 同じカメラで解像度を
  上げる時も (b) フィルムバックを広げた別のカメラの時もある」「ビューアーで見えていれば OK」。→ レイヤーごとの書き出しの設定は
  持たない。ビューアーは AE のコンポと同じく、コンポの大きさの枠に各レイヤーの「AE で見えている部分」を重ねる。そのため
  Maya レイヤーのカメラには、(b) の場合も大判を出すカメラではなく、**コンポの画角のショットのカメラ**を選ぶ（大判のカメラは
  BG の素材を出すときだけ使う）。(a) の場合も、レンダー解像度は余白付きでよい（D-36）。

## 4. 将来の構成（Phase 1 以降の方針）

- **サーバー:** FastAPI + WebSocket、`127.0.0.1` のみで待ち受ける。起動時にセッショントークンを発行し、
  ユーザーごとの一時ファイルで共有する。多重起動はロックファイル＋ポート確認で防ぐ。
  クライアント（Maya／AE のインスタンス）は接続時に `source_id`（アプリ名、PID、シーン／プロジェクト）を名乗る。
- **同期:** メッセージは `envelope.make()` の形式（`event_id`、`source_id`、`revision`）。サーバーはリビジョンを管理し、
  自分が送った変更の反映（エコー）を無視する。同時編集は競合として利用者に選ばせる。
- **Maya:** 受信処理は `maya.utils.executeDeferred` でメインスレッドに渡す。
- **AE:** CEP 側でメッセージをキューに入れ、`evalScript` で順に JSX を呼ぶ。変更検出はポーリング＋ハッシュ。
- **配布・更新（Phase 6）:** `SyncServer.exe` と `SyncUpdater.exe` を PyInstaller で作る。更新パッケージは
  署名し、アプリに同梱した公開鍵で検証する（SHA-256 だけでは真正性を保証できない）。
  更新チャンネルは development／stable を分け、stable はタグ付きリリースだけにする。
