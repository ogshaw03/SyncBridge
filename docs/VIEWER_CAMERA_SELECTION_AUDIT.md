# ビューアーの編集中レイヤー自動切り替え: コード調査（2026-10-28）

> **このレポートだけを読む人へ（前提）**
>
> - SyncBridge は、Maya と After Effects の間でカメラ・時間を同期するツールです。
> - 「ビューアー」は Maya の中の専用のウィンドウで、Viewport 2.0 のレンダーオーバーライド（Python API 2.0 のプラグイン）を使い、
>   複数の「SyncBridge レイヤー」を AE のレイヤーのように重ねて描きます。
>   - SyncBridge レイヤーは、カメラ 1 台と表示するオブジェクトの組です。シーンの network ノードに JSON で記録します。
>   - 各レイヤーは、そのレイヤーの「専用カメラ」で別々に描かれます。
> - Maya の選択とマニピュレーターは、パネルのカメラ 1 台でしか動きません。
>   そこで、ある 1 つのレイヤーを「編集中」にし、パネルはそのレイヤーの専用カメラの子の「ビューカメラ」（`SB_VIEWER_CAM`）を通して見ます。
>   こうすると、編集中のレイヤーだけは Maya 標準の選択・移動が見た目と一致します。
> - ほかのレイヤーのオブジェクトをクリックすると、SyncBridge がレイヤーごとのカメラで光線を当てて判定し、そのレイヤーを編集中に切り替えます。
> - このレポートは、その切り替えと選択の問題を、コードの調査（1〜7 章）と Maya 2023 / 2024 での自動検証（8 章）で調べ、直し方の計画（9 章）を書いたものです。
> - 記号の D-xx は設計判断（`docs/ARCHITECTURE.md`）、H-MY-xx は Maya の API の仮説と検証（`docs/PHASE0_RESEARCH.md`）です。
> - 行番号は 0.1.14 の作業ツリーのものです。

対象は SyncBridge ビューアー（D-33 / D-44）の「選択に応じて、操作に使うカメラ（編集中レイヤーのビューカメラ）を切り替える」処理です。
**この調査ではコードと UI を変えていません**（9 章は計画で、まだ実装していません）。 調査したのは 0.1.14 の作業ツリーです（プラグイン r14、`ca8ead7` からの変更はまだコミットしていません）。

分類の記号は次のとおりです。

| 記号 | 意味 |
|---|---|
| ✅ | コードを読んで、正しく処理されていることを確認した |
| ⚠️ | 問題になる可能性がある（コードから読み取れる設計上の弱点） |
| ❌ | コードに不具合がある（動作がはっきり誤っている） |
| ❓ | Maya で試さないと判断できない |

## 0. 最初に押さえておくこと（依頼の前提とコードの違い）

依頼文は「オブジェクトを選択すると、そのオブジェクトのレイヤーの専用カメラへ切り替わる」という前提で書かれています。しかし、**コードは「選択の変化」を監視していません。**
切り替えのきっかけは次の 2 つだけです。

1. ビューアーのビューの中での**左クリック**（押して離す。4px 以内のずれまで）
   - `viewer_window.py` の `eventFilter`（214–233 行）と `_click`（235–251 行）
2. ビューアー下のレイヤー一覧の**行のクリック**
   - `layer_stack_view.py` の `_on_clicked`（88–90 行）が `editing_requested` を出し、`viewer_window.py` の `set_editing`（154 行で接続）が受け取る

`SelectionChanged` の scriptJob も、`MEventMessage`、`MModelMessage` のコールバックも、ビューアーにはありません（`maya_plugin/` 全体を検索して確認）。
そのため、次の操作で選択が変わっても、**編集中のレイヤー（カメラ）は変わりません。**

- アウトライナーでの選択
- 普通のビューポートでの選択
- スクリプトでの選択
- 囲み選択（ドラッグ）
- Ctrl を押しながらのクリック

この前提を踏まえて、以下を読んでください。

設計の要点は次のとおりです（D-44、H-MY-38 / 40 / 42）。

- Maya の選択とマニピュレーターは、パネルのカメラ（ビューカメラ）1 台だけを使う。
- そのため、**編集中のレイヤーだけが、Maya 標準の選択・移動と見た目が一致する。**
- ほかのレイヤーのクリックは、SyncBridge が自分で光線を当てて判定し、そのレイヤーを編集中にしてから選択し直す。

## 2. カメラ自動切り替えの処理フロー

```
[ビューの左ボタンを押す]  eventFilter 221–226
   ├ Alt / Ctrl が押されている → 何もしない（タンブル・トグル選択は対象外）
   └ (位置, その時点の選択) を self._press に覚える
   → Maya にもイベントを渡す（Maya の選択・マニピュレーターはふだんどおり）

[離す]  eventFilter 227–232
   ├ 押した位置から 4px を超えて動いた → ドラッグ（マニピュレーター・囲み選択）として何もしない
   └ クリック → QTimer.singleShot(0) で _click を予約（Maya のクリック選択が終わった後に動く、H-MY-40 ✅）

[_click]  235–251
   1. マニピュレーターのクリックかどうかを見る（241–243）
      Shift なし、押す前に選択があった、選択が変わっていない、
      かつ on_selection() が False（クリック位置に選択中のメッシュがない）→ 何もしない
   2. store = layer_mapping.store()（シーンの JSON を毎回読む）
   3. hit = viewer_pick.pick(...)                    … 上のレイヤーから光線で判定
   4. hit が None、または hit のレイヤーが今の編集中 → 何もしない（Maya の選択をそのまま残す）
   5. set_editing(hit.layer)                          … カメラを切り替える
   6. cmds.select(hit.node, replace / add)            … 当たったメッシュのトランスフォームを選ぶ

[set_editing]  258–273
   ├ レイヤーに専用カメラがない → エラーの表示だけ
   ├ self._editing = layer_id
   ├ _sync_view(store)  349–370
   │   ├ _apply_editing  275–291
   │   │   ├ 描けるレイヤー（非表示も含めて扱う）に編集中がなければ、いちばん上のレイヤーにする（279–280）
   │   │   ├ 切り替える前のビュー（view_affine）を取っておく  _current_view 299–313
   │   │   ├ viewer_camera.ensure(新しい専用カメラ)  … 作り直さず、親を付け替える（_follow 189–197）
   │   │   └ 同じ見え方になる pan / zoom を設定する  _keep_view 315–324（core.match_view）
   │   ├ layer_stack.publish()  … __main__ の状態を更新し、scheduleRefreshAllViews（強制再描画はしない）
   │   └ パネルのカメラ: UUID が違うときだけ modelEditor -camera（365–367、Maya 2024 の落ちる不具合を避けるため）
   └ refresh()  … 30ms 後にまとめて、一覧・専用カメラの修復・_sync_view をもう一度行う

[描画]  プラグイン setup → _build（state の version が変わったときだけ作り直す）→ _view
   レイヤーのパス × N（マニピュレーターを除く）→ マニピュレーターのパス（ビューカメラ）→ HUD（枠）→ 表示
```

### 異なるカメラのオブジェクトを同時に選んだときのマニピュレーター（重要）

- マニピュレーターのパスは**ビューカメラ 1 台**で描かれます（`ManipulatorPass.set_camera`、プラグイン 201–207 行、`_build` 451 行）。
  `objectSetOverride` はマニピュレーターを絞りません（H-MY-42 ✅）。
- したがって、**編集中でないレイヤーのオブジェクトが選択に入っていると、次のようになります。**
  - そのオブジェクトの**見た目の位置**: そのレイヤーの専用カメラで投影した位置
  - Maya が置く**マニピュレーター**: そのオブジェクトのワールド位置を**ビューカメラ（編集中のレイヤーのカメラ）**で投影した位置

  両者は一致しません。移動ツールのピボットは選択の平均なので、ピボットも「どちらのレイヤーの見た目とも合わない」位置になりえます。
- ドラッグしたときの移動量は、ビューカメラから見た画面の動きで決まります。そのため、ほかのレイヤーのオブジェクトの**画面上の動き**は、マウスの動きと一致しません。
  ワールド空間での移動はどのオブジェクトにも同じ量が入るので、**データとしては壊れません**（アニメーションキーも、通常の Maya の移動と同じ扱いです）。
- **選択のハイライト**（ワイヤーフレーム）は、レイヤーのパスごとに専用カメラで描かれます。見た目のハイライトとマニピュレーターの位置がずれて見える、という形で現れます。
- 同じことが、次の場合にも起きます。
  - **一覧の行をクリックして編集中を変えたが、選択は前のレイヤーのまま**（`set_editing` は選択を変えない、258–273 行）
  - **アウトライナーでほかのレイヤーのオブジェクトを選んだ**

  → **⚠️ P-2: コード上は確実に起きる不整合です。** 画面上のずれの大きさは、カメラの違い次第です（❓ 実機で見え方を確認）。

## 4. 未登録オブジェクト選択の調査結果

| ケース | コードから分かる今の動作 | 分類 |
|---|---|---|
| どのレイヤーにも登録していない普通のオブジェクトを選ぶ | ビューアーには描かれない（各パスの `objectSetOverride` = そのレイヤーのオブジェクトだけ、プラグイン 179–180 行）。アウトライナーで選んでも**カメラは今のまま**。マニピュレーターは、ビューカメラから見たワールド位置に**オブジェクトなしで**出る（P-3） | ✅（失敗はしない） / ⚠️ |
| ビューアーで、未登録のオブジェクトがある場所をクリック | `pick` は登録済みのメッシュしか調べないので、当たらない → 何もしない。しかし **Maya 自身のクリック選択はビューカメラで行われ、描かれていない未登録のオブジェクトを選ぶ可能性がある**（Maya の選択がレンダーオーバーライドの `objectSetOverride` に従うかは未確認） | ❓（P-1） |
| 未登録と登録済みを同時に選ぶ | Shift のクリックで登録済みに当たれば、そのレイヤーへ切り替わり、未登録のものは選択に残る。未登録のものは見えないまま、マニピュレーターのピボットに入る | ⚠️ |
| 選択中のオブジェクトのレイヤーを削除する | レイヤーマップでの削除 → `service.announce("layer_map")` → `on_event` → `refresh`。`_apply_editing` が、**編集中のレイヤーがなくなったので、いちばん上の描けるレイヤーへ移す**（279–280 行）。選択はそのまま（削除された専用カメラの子のビューカメラは `layer_camera.delete` で一緒に消えるので、`ensure` が作り直す ❓）。基準カメラ（`view_camera`）に戻るのは、描けるレイヤーが 1 つもないときだけ（282–284 行 → 361 行） | ✅ / ❓ |
| 表示中のレイヤーを非表示にする | 非表示でも、編集中は**そのまま**（`_apply_editing` が `visible=True` として扱う、277–278 行）。そのレイヤーは描かれないが、パネルはそのビューカメラで見ている。Maya の選択とマニピュレーターは、**見えないレイヤーの視点**で動く。`pick` は非表示のレイヤーを除くので、見えている別のレイヤーをクリックすれば切り替わる | ⚠️（P-5） |
| 選んだオブジェクトを別のレイヤーに登録し直す | `pick` はクリックのたびに `store()` を読み直すので、次のクリックから新しい登録で判断する。今の編集中は自動では変わらない | ✅ |
| リグの階層の中で、選択ノードと登録ノードが違う | `_meshes`（56–60 行）は、登録ノード配下のすべてのメッシュを対象にする（中間オブジェクトを除く）。ほかのレイヤーで当たったときに選ぶのは**メッシュの親のトランスフォーム**で、登録ノード（グループやリグのルート）でもコントローラーでもない（96 行）。編集中のレイヤーの中では、Maya 自身の選択（選択マスク・選択の優先度）がそのまま使われる。**ほかのレイヤーのクリックだけが `cmds.select` で直接選ぶので、選択マスク・リファレンス表示レイヤー（選べない設定）・テンプレートを無視する** | ⚠️（P-6） |
| カメラ・ロケーター・NURBS カーブのコントローラーを選ぶ | `pick` はメッシュしか調べない（`_meshes`）。ほかのレイヤーのカーブやロケーターをクリックしても**切り替わらない**。登録ノードの子なら描かれてはいる（`objectSetOverride` は子も描く、H-MY-33）。カメラは登録時に除かれる（`selected_objects` 198–208 行）。NURBS サーフェスも対象外 | ⚠️（P-7） |

**答え: 未登録のオブジェクトを選んだとき、ビューアーは「今のカメラを保つ」動作をします。** 基準カメラには戻りません。選択の処理が失敗することもありません。
基準カメラに戻るのは、描けるレイヤーが 1 つもなくなったときだけです。

### 9.1 P-11: 編集中のレイヤーを替えると、選択がビューカメラに置き換わる（最優先）

- **原因:** `viewer_camera.py` が、次の場面で Maya の選択を変えてしまう。
  - `_follow` の `cmds.parent`（194 行）
  - `_create` の `cmds.camera`（220 行）
  - `_fold` の `cmds.createNode`（243–246 行）

  mayapy 2024 で確認済み（H-MY-44）。
- **直し方:** `viewer_camera.py` に、選択を取っておいて戻すコンテキストマネージャ `_keep_selection` を足す。
  - 入るときに `cmds.ls(selection=True, long=True)` を取る。
  - 出るときに、そのうちまだあるノードを `cmds.select(..., replace=True, noExpand=True)` で選び直す（なければ `cmds.select(clear=True)`）。
  - 出るときの処理は `_no_undo` の中で行い、undo の履歴に積まない。
  - これで `ensure`（作る・付け替える）と `remove`（消す）の全体を包む。
  - 戻す選択からは、ビューカメラ自身（`MARK_ATTR` の付いたノード）を除く。
- **選ばなかった案:** `cmds.parent` を `om2.MDagModifier.reparentNode` に替える案。`parent` には効くが、`camera` と `createNode` には別の対処が要る。包む方が 1 か所で済む。
- **確かめ方:** `gui_sel_check.py` で次の 4 つを確かめる。
  - R-1（行のクリックで選択が変わらない）
  - T-4（Shift のクリックで CHAR が残る）
  - T-9（レイヤーの削除で選択が計算用のノードにならない）

### 9.2 P-4: Shift のクリックの扱いが Maya と違う

- **原因:** `viewer_window.py` の `eventFilter`（224–231 行）が、Shift を「追加」として扱い、Ctrl を含むクリックを無視している。Maya では次のとおり。

  | 操作 | Maya の意味 |
  |---|---|
  | Shift | トグル |
  | Ctrl | 外す |
  | Ctrl+Shift | 追加 |

- **直し方:** 押したときに、修飾キーから `mode` を決める。

  | 操作 | mode |
  |---|---|
  | なし | `"replace"` |
  | Shift | `"toggle"` |
  | Ctrl+Shift | `"add"` |
  | Ctrl だけ | 監視しない（外すだけでカメラは替えない） |

  `_click` の最後（248–249 行）を次のように分ける。

  | mode | 当たったノードの状態 | すること |
  |---|---|---|
  | toggle | 押す前から選ばれていた | `cmds.select(node, deselect=True)` で外し、**編集中は替えない** |
  | toggle | 選ばれていなかった | `add=True` で足し、編集中を替える |
  | add | — | 足して、編集中を替える |
  | replace | — | 今までどおり |

  マニピュレーターのクリックの判定（241–243 行）は、replace のときだけ行う（今と同じ）。
- **確かめ方:** T-5 で、Shift のクリックで CHAR が外れ、編集中が替わらないこと。Ctrl+Shift のクリックで追加されること。

### 9.3 P-1: Maya の選択が、ビューアーに描かれていないものを選ぶ

ビューアーの中で Maya が選べるものを、「編集中のレイヤーのオブジェクト（とその子）」に限りたい。

ほかのレイヤーは、今までどおり SyncBridge の `pick` で選ぶ（クリックで編集中を替える）。

- **第 1 案（先に試す）: モデルパネルの Isolate Select を使う。**
  - ビューアーのパネルだけで `cmds.isolateSelect(panel, state=True)` にし、編集中のレイヤーのオブジェクトだけを入れる。
  - 編集中が替わるたびに、中身を入れ替える（`isolateSelect -addDagObject / -removeDagObject`、または `-loadSelected` の代わりに専用のセットを使う）。
  - Isolate Select は Maya 自身のクリック・囲み選択の対象も絞る。そのため、Maya の標準の選択をそのまま使える。
  - シーンのノードの設定（表示・選択の可否）は変えない。パネルの表示の設定だけで済む。
  - **未確認（H-MY-45 として先に確かめる）:**
    - Isolate Select をオンにしても、レンダーオーバーライドの各パスの `objectSetOverride` が、ほかのレイヤーのオブジェクトを描くか。
    - 絞られてほかのレイヤーが消えるなら、この案は使えない。
    - あわせて、Maya 2023 / 2024 で選択が本当に絞られるか（クリック・囲み）。
- **第 2 案（第 1 案が使えないとき）: 選択の後で取り除く。**
  - 左ボタンを離したとき（クリックでもドラッグでも）に、押す前と後の選択を比べる。
  - 新しく選ばれたノードのうち、編集中のレイヤーに属さないものを `cmds.select(deselect=True)` で外す。
  - 属するかどうかは、登録ノードの UUID と、その祖先・子孫の関係で判断する（9.5 の関数を使う）。
  - マニピュレーターのドラッグでは選択が変わらないので、何もしない。
  - 欠点:
    - 一瞬選ばれてから外れる。
    - undo の履歴が 1 つ増える。
    - アウトライナーで見えないものを選んだ場合は対象外（それは利用者の意図なので、外さない）。
- **選ばなかった案:** ほかのレイヤーのオブジェクトを、テンプレートや選択不可（`overrideDisplayType`・`selectable`）にする案。シーンとリグを書き換えるので行わない。
- **確かめ方:** T-1・T-2・T-3・T-8・T-11 で、描かれていないものが選ばれないこと。編集中のレイヤーでは、今までどおり選べ、マニピュレーターでドラッグできること（H-MY-42 の確認の再実行）。

### 9.4 P-5: 非表示のレイヤーが編集中になる

- **直し方:** `viewer_window._apply_editing`（277–280 行）の候補を、**表示中で描けるレイヤー**だけにする（`visible=True` を強制しない）。
  - 編集中のレイヤーが非表示にされたら、表示中の一番上のレイヤーへ移す。
  - 表示中のレイヤーが 1 つもなければ、編集中なし（`viewer_camera.remove()`、今の「描けるレイヤーがない」ときと同じ）。
  - 一覧で非表示の行をクリックしたときは、編集中にせず、状態の行に「表示してから選んでください」と出す。
- **注意:** 枠と見るカメラの決め方（`core.layer_mapping.view_camera_uuid` は非表示も含める、D-33）とは別の話で、そちらは変えない。
- **確かめ方:** T-8（非表示にすると表示中のレイヤーへ移る）、T-9（削除の後に、非表示の CARD ではなく表示中のレイヤーへ移る）。

### 9.5 P-2 / P-3 / P-9: 混ざった選択と、選択の変化でのカメラの切り替え

- **共通の関数（core に、純 Python で、単体テストを書く）:** `layers_of_nodes(store, node_uuid_paths)`
  - 入力: 選択ノードの UUID と、その祖先の UUID の列。
  - 出力: 各ノードが属するレイヤーの ID の一覧。
  - 判定: 祖先をたどって最初に当たった登録ノードのレイヤー。リグの子を選んでも、登録したルートのレイヤーになる。
  - 1 つのノードが複数のレイヤーに登録されていたら、全部を返す。
  - Maya 側では、`cmds.ls(selection=True, long=True)` の各ノードとその祖先の UUID を集めて渡す。
- **選択の変化でカメラを切り替える（依頼の「選択に応じた自動切り替え」を、アウトライナーなどにも広げる）:**
  - ビューアーが開いている間だけ、`cmds.scriptJob(event=["SelectionChanged", ...], parent=<ビューアーのパネル>)` を登録する。閉じると Maya が自動で消す。
  - 選択が**すべて 1 つの、表示中のレイヤー**に属するときだけ、そのレイヤーを編集中にする。
  - 混ざっているとき、未登録のものを含むとき、空のときは、今のカメラを保つ。
  - 同じレイヤーに複数登録されていれば、今の編集中を優先し、なければ上のレイヤー。
  - ビューアー自身の `_click` が `cmds.select` する間は、フラグで無視する（二重の切り替えを防ぐ）。
  - 切り替えは選択を変えない（9.1 の後）ので、ループしない。
  - Undo で選択が戻ったときも、この scriptJob がカメラを戻す（P-9 の解消）。
  - 決めてもらうこと: 利用者が「アウトライナーで選んでもカメラが替わる」ことを望むか。オフにできる設定（optionVar）を付けるかどうかは、利用者の判断。
- **混ざった選択の知らせ（P-2 / P-3）:**
  - 選択に、編集中でないレイヤーや未登録のオブジェクトが含まれるとき、ビューアーの状態の行に次のように出す。
    > マニピュレーターは「BOOK」の見え方です。CHAR は別のレイヤーなので、見た目の位置とずれます
  - 選択は変えない。
- **確かめ方:**
  - 単体テスト: 祖先・複数登録・未登録・空。
  - GUI: T-6（アウトライナー相当の選択でカメラが替わる）、R-2b（混ざった選択でメッセージが出て、カメラは替わらない）、T-10（Undo でカメラが戻る）。

### 9.6 P-6: 選べない設定のオブジェクトを、ほかのレイヤーのクリックで選んでしまう

- **直し方:** `_click` で、`cmds.select` の前に当たったノードが選べるかを確かめる。
  - ノードと祖先の `overrideEnabled` / `overrideDisplayType`（Template・Reference）

  選べないときは、**編集中だけを替え、選択はしない**。状態の行に理由を出す。
- **確かめ方:** T-13 で、BOOK は選ばれず、編集中は BOOK になる。

### 9.7 P-7: メッシュ以外（カーブ・ロケーター）のクリックで切り替わらない

  - ロケーターは、ワールド位置を投影する。
  - メッシュの光線の判定と同じく、上のレイヤーから調べる。
- **確かめ方:** T-11 で、円をクリックすると BOOK が編集中になり、円が選ばれる。

## 13. 9.5（P-2 / P-3 / P-9）の修正と検証（2026-10-28）

### 実装

| 場所 | 変更 |
|---|---|
| `src/syncbridge/core/layer_mapping.py` | `selection_layers(layer_roots, selection, editing)` を足した。単体テスト 3 件 |
| `viewer_window.py` の `_follow_selection` | ビューアーが開いている間だけ `SelectionChanged` の scriptJob で動く（30ms にまとめる。閉じると消す） |
| `viewer_window.py` の `_note_selection` | 状態の行に、マニピュレーターが合わない理由を出す |
| `viewer_window.py` の `say` | `warn`（色だけ。スクリプトエディタには出さない）を足した |

`selection_layers` の決め方は次のとおり。

- 選択のすべてのノードが、表示中の 1 つのレイヤーに属するときだけ、そのレイヤーを `target` にする。属するとは、登録ノード・その子・その親（`related`）のこと。
- 2 つ以上のレイヤーに当てはまるときは、今の編集中を優先し、なければ上のレイヤーにする。
- 混ざった選択、未登録（または非表示のレイヤー）のものを含む選択、空の選択では、`target` は None にする（今のカメラを保つ）。

`_follow_selection` は、選択が**前回見たときから変わったときだけ**切り替える。理由は次の 2 つ。

- ビューカメラを動かした後で選択を戻す処理（P-11）も `SelectionChanged` を起こす。
- 一覧の行で選んだ編集中のレイヤーが、すぐ元に戻ってはいけない。

`_note_selection` が出す知らせは次の 2 種類。

- 未登録・非表示のもの: 「選択の UNREG は、ビューアーに描かれていません…マニピュレーターだけが『CHAR』の見え方で出ます。」
- 別のレイヤーのもの: 「選択に『BOOK』のレイヤーのものが入っています。マニピュレーターは編集中の『CHAR』の見え方なので…合いません。」

選択が合えば、知らせは消える。

### 結果

全テストは、標準ライブラリの 396（106 スキップ）、`.venv` の 396 とも OK だった。

| S-3 | UNREG を選ぶ | BOOK のまま。「選択の UNREG は、ビューアーに描かれていません…」と出た ✅ |
| S-4 | CHAR を選ぶ | CHAR に切り替わった ✅ |
